# Configuration

Each ifthenpay payment method is configured as its own Drupal Commerce payment
gateway, and each needs the matching credentials from your ifthenpay account plus a
callback URL registered in the ifthenpay backoffice.

## Add a gateway

1. Log in as a user who can **administer commerce payment gateways**.
2. Go to **Commerce → Configuration → Payment gateways**
   (`/admin/commerce/config/payment-gateways`) and click **Add payment gateway**.
3. Give it a **Name** and select the ifthenpay plugin for the method you want
   (Multibanco, MB WAY, or credit card).
4. Enter the credentials for that method (see below) and set the **Mode** to
   **Test** (sandbox) while integrating, then **Live** for production.

## Credentials by method

- **Multibanco references** — for the recommended dynamic (API) mode, enter your
  **MB key** assigned by ifthenpay. References are then generated by ifthenpay with
  full-length order IDs and no collisions. Payment confirmation arrives via the
  ifthenpay callback, validated with your **anti-phishing key**. The offline
  entity/sub-entity mode is available for accounts without an MB key.
- **MB WAY** — configure the MB WAY credentials so the checkout can send the
  payment push to the customer's phone.
- **Credit card** — enter your **credit-card key** (`cccard_key`); the return
  handler uses it to verify ifthenpay's security key on each payment.

## Register the callback URLs

The confirmation of a payment depends on ifthenpay calling back to your site.
Register the callback URLs the module exposes in your **ifthenpay backoffice** for
each method (the exact URLs and the anti-phishing key setup are documented in the
module's README). Without the callbacks registered, Multibanco payments will not be
confirmed automatically.

## Store your ifthenpay keys securely

The MB key, anti-phishing key and credit-card key are secrets — keep them out of
version control. Store each value in an environment variable and reference it
through a **Key** entity where the module supports one:

```bash
ddev dotenv set .ddev/.env --ifthenpay-mb-key=<your-key>
ddev restart
```

If the [Key module](https://www.drupal.org/project/key) is not enabled yet, add it
with `ddev composer require drupal/key && ddev drush en key -y`, then create a Key
that reads the environment variable. Always run ifthenpay over HTTPS.

## How payments are confirmed (why this is safe)

- **Multibanco** confirmation is done by the module **polling ifthenpay's API
  server-side** — the API's status is authoritative, so there is nothing in the
  browser a shopper could forge.
- **Credit card** returns are verified: the module recomputes ifthenpay's security
  key `SK = SHA-256(orderId + amount + requestId + card key)` and compares it with
  a strict check, and it re-verifies the charged amount against the order amount.
  Any mismatch throws an error and the order is not completed. Forged or tampered
  returns are rejected.

There is nothing extra you need to harden beyond keeping the keys confidential and
registering the callbacks correctly.
