Translate View Path makes path aliases work for view paths in a multilingual site, including the segmented paths that Facets Pretty Paths produces.

---

Aliases and views do not fit together as neatly as people expect. A view's path is a route, not an entity, so it has no alias in the ordinary sense, and once a faceted search starts appending segments — `/products/colour/red/size/large` — the whole path is generated by a module rather than stored anywhere. In a multilingual site that becomes a real problem: the French visitor gets English path segments, which is bad for the reader and worse for search engines, since the localised URL is a significant part of how a page ranks in its own language. This module processes those paths so the aliases apply, with the module's own description naming Facets Pretty Paths as the case it handles well. It works as an inbound and outbound **path processor** (`TvpProcessor`), which is the correct mechanism — the same one core uses for language prefixes — meaning the URL is translated at generation and resolved back on the way in, rather than being rewritten after the fact. Version **1.1.2** on `^8.8.0` through `^11`, depending on core `path_alias` and `views`. Two things to check: **path processors run on every request**, so keep the alias lookups tight; and **round-tripping** is what to test — every generated URL must resolve back to the same view state in the same language, including when a facet value is itself translated.
