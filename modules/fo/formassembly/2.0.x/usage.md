FormAssembly integrates Drupal with the FormAssembly service, so forms built and hosted there — typically because they feed Salesforce — can be rendered as Drupal entities on the site.

---

FormAssembly is a form platform used mainly in Salesforce-centred organisations, where the form's value is its connection to CRM objects rather than to Drupal. Rendering such a form on a Drupal site usually means an iframe, which breaks styling, accessibility and analytics. This module takes the better route: a `fa_form` **configuration entity** represents each remote form, the module fetches the form markup over the API, and `symfony/dom-crawler` plus `symfony/css-selector` are used to parse and adapt that markup for rendering inside the page. Authentication is OAuth, handled by `fathershawn/oauth2-formassembly` with `ApiAuthorize` and a two-step admin flow — `/admin/structure/fa_form/settings/authorize` sends the site off to authorise, and `.../settings/code` captures the returned authorization code — both gated by `administer formassembly form entities`, which is marked `restrict access: true`. Four permissions in total separate administering, editing, listing and viewing the form entities. Requirements include `map_widget ^2.0`, PHP's `libxml` and `json` extensions, and core `^10 || ^11`. Note that entity routes are generated by `FormAssemblyEntityHtmlRouteProvider` rather than declared, so the routing file shows only the OAuth endpoints.
