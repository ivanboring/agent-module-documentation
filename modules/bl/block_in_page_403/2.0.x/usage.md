Block In Page 403 provides the ability to place a block on the 403 access-denied page.

---

Block In Page 403 lets site builders place a block on the 403 (access denied) page — so the
access-denied response can show custom content (a login prompt, a help message, a contact link) via a
block, rather than the bare default 403. It depends on core Block and is in the Administration package.

Use it to make the 403 page more helpful. It is an administration/UX feature affecting the 403 page content;
the placed block keeps its own access and the 403 itself still denies access to the requested resource — it
only enriches the denial page. No access-control role. Place the block in the 403 context.
