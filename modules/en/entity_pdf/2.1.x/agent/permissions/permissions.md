# Entity PDF — permissions & access model

## Declared permissions (`entity_pdf.permissions.yml`)
| Permission | Restricted? | Gates |
|---|---|---|
| `administer entity pdf settings` | `restrict access: true` | The settings form. |
| `view entity pdf` | no | View the PDF for **all** entities (title: "View PDF for all entities"). |
| `view <entity_type>.<bundle>.<view_mode> pdf` | no (dynamic) | Per view-display PDF access. |

The dynamic permissions are generated by `EntityPdfPermissions::permissions()` — one per
`entity_view_display` config entity, e.g. `view node.article.pdf pdf`.

## Where they are enforced
- Route `entity_pdf.node`: `_permission: 'view entity pdf'`.
- Route `entity_pdf.view`: `PdfEntityController::access()` = `view entity pdf` OR the matching
  per-display permission.
- Bulk action `EntityPdfDownload::access()` = `view entity pdf` OR `view node.<bundle>.<mode> pdf`.

## Access caveat (important)
None of these checks call `$entity->access('view')`. Holding `view entity pdf` (or a per-display
`view … pdf` permission) is sufficient to render the entity's content as a PDF **regardless of the
entity's own view access** — including unpublished nodes and content otherwise gated by node-access
modules. Both these permissions are non-restricted, so granting them to a low-trust role widens
read access to content that role cannot see through normal routes. See
[../../security.md](../../security.md) (module root, local-only). Grant `view entity pdf` only to
roles you trust to read every entity, or rely solely on the per-display permissions and understand
they still ignore per-entity access.
