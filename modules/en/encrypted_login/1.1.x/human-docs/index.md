# Encrypted Login — manual setup guide

**Encrypted Login** (`encrypted_login`) encrypts login credentials **in the
browser** before they are submitted to Drupal's standard login form. It generates
an RSA-2048 key pair when it is installed, exposes the public key through an
endpoint, and the browser uses a hybrid RSA/AES scheme (a fresh AES-256 key per
login, wrapped with the RSA public key) to encrypt the password; the server then
decrypts it with the private key and runs normal Drupal authentication. It
depends only on core's **User** module.

> **Read this before adopting it — it is not a substitute for HTTPS/TLS.** When
> your site is served over HTTPS (which it must be), TLS *already* encrypts
> credentials in transit, so encrypting them again in JavaScript adds limited real
> protection against a network attacker and can create a false sense of security.
> Never treat this module as a reason to serve login over plain HTTP — always keep
> TLS enforced. It also introduces custom cryptography around authentication and a
> server-side private key that you must protect. It does **not** change who can log
> in.

The module is designed to work with the standard login form once enabled, so for
most sites there is nothing to click through. The main operational concern is
**key management**: the RSA private key is generated at install and held in
Drupal's state system, and the project's own guidance recommends rotating the RSA
keys periodically and keeping a secure backup. There is no dedicated
configuration screen documented for this module.

This guide is written for a **human** clicking through the admin UI. If you want
terse, token‑cheap references for an AI coding agent, read the sibling
[`agent/`](../agent/start.md) docs instead.

## How to use it

1. Ensure your site is served over **HTTPS** (required — see the caveat above).
2. Install and enable the module (see [Installation](installation/index.md)).
3. Confirm the RSA key pair was generated by checking the **Status report**
   (`/admin/reports/status`).
4. Use the normal login form — credential encryption happens automatically in the
   browser.

> **Secret and key handling.** The RSA private key is the sensitive material
> here. Keep a secure backup, consider rotating the keys on a schedule (the
> project suggests roughly every six months), and monitor logs for decryption
> failures. Because the module relies on the browser's Web Crypto API, it needs a
> modern browser and PHP's OpenSSL extension.
