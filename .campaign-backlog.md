## Version-selection rule (decided wave 2)
`composer require drupal/x` resolves to the highest *stable* release, which can be an
older, D9-only major when the D11-compatible one is a pre-release of a higher major.
Caught by `scripts/check-major.sh`. media_directories hit this: stable 2.0.2 is
`^8.8.3 || ^9`; we moved it to 3.0.0-beta1 (`^10.2 || ^11 || ^12`).

Rule applied: take the highest major that has a real tagged release supporting D11.
Do NOT downgrade a working stable D11 release to an alpha/dev of a higher major, and
ignore majors that exist only as dev branches. Wave-1 audit flagged three projects under
this rule and all three were correctly left alone:
  - config_override_warn 1.5.0 — 2.x is dev-branch only
  - block_classes 1.0.4      — 2.0.x is dev-branch only
  - views_entity_form_field 1.2.0 (stable, ^10.1||^11) — 2.x is only 2.0.0-alpha1

Note `drush en` is itself a D11 compatibility gate: a module that enables is D11-compatible,
so wave-prepare.sh's FAILED column catches the incompatible-major case automatically.
